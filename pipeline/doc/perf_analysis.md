## 1. 评价指标的选择与依据（要求点①）

### 1.1 候选指标与取舍

| 指标 | 含义 | 优点 | 局限 | 本实验采用 |
|---|---|---|---|---|
| **CPI** | 每指令拍数 = C/IC | 与时钟、工艺无关，**直接暴露流水线设计效率**（停顿就是 CPI 超 1 的部分） | 单一数字掩盖停顿构成 | **主指标** |
| **IPC** | 每拍指令数 = 1/CPI | 与"结构加速比"同值，便于与大三单周期直接对照 | 与 CPI 冗余 | **采用（作对照列）** |
| **MIPS** | 每秒百万条指令 | 直观、可与教科书对照 | **依赖时钟频率**，跨设计比会混入频率因素 | **采用（频率维度）** |
| **CPU 时间** | C × Tclk | 端到端完成时间，最贴近"跑得快不快" | 同上依赖频率 | **采用（频率维度）** |

### 1.2 依据（写进报告的三句话）

1. **流水线设计的目标是"在不牺牲吞吐的前提下缩短关键路径"**，因此最能反映设计质量的是**与频率无关的 CPI**——它把"设计效率"和"工艺/频率"两个因素分开；
2. 单周期 CPU 的 **CPI ≡ 1**（每条指令一拍完成，无填充、无停顿），是所有对比的天然基准线；因此 **CPI 之比 = 结构加速比**，可直接量化"流水线为换取频率付出了多少吞吐代价"；
3. **MIPS 与 CPU 时间必须报，但只在"频率维度"报**——因为流水线的收益来自可达到的最高频率，这两个指标用来回答"提频收益能否覆盖 CPI>1 的损失"。

> 报告口径句："我们以 **CPI 为主指标、IPC 为对照、MIPS 与 CPU 时间用于频率维度**；选择依据是 CPI 与频率解耦，能单独衡量流水线设计效率。"

## 2. 测量口径（口径唯一、可复现）

### 2.1 时间窗口（三口径）

| 窗口 | 定义 | 用途 |
|---|---|---|
| `C_total` | 复位释放 → 停机自旋首个真实 EX 槽 **+ D 拍**（停机尾，实测） | 端到端完成时间 |
| **`C_steady`** | `C_total − C_fixed = IC + L + 2T − 3` | **主口径**（剔除停机指令与冲刷尾） |
| `C_fixed` | `1 + D = 3`（停机自旋 1 拍 + 冲刷尾 `D=2`） | 解释"短程序 CPI 偏高" |

> **为什么对比用 `C_steady`**：单周期基线 `IC` 不含"复位填充 + 停机冲刷尾"这类**流水线特有开销**；若用 `C_total` 对比，等于把自己的固定开销算进去、低估流水线。

### 2.2 符号与判据（全部可测量）

| 符号 | 判据 |
|---|---|
| `IC` | **EX 槽控制字非全零**的真实指令槽数，包含末尾停机自旋指令（气泡/复位槽控制字全零；不用 `inst≠0/0x13` 判据） |
| `IC_useful` | `IC − 1`，剔除末尾停机自旋后的有效程序指令数 |
| `F` | 首个真实 EX 槽的沿号（实测，期望 1） |
| `L` | `stall` 拉高沿数（load-use 冻结） |
| `T` | `br_taken` 有效次数（分支 taken + `jal/jalr`） |
| `h` | 停机自旋首个真实 EX 槽沿号（真实槽 + `idex_pc==br_target` **连续 2 拍**成立） |
| `D` | 停机尾拍数（实测，v1.0 实测为 2） |

### 2.3 指标公式与自检

| 指标 | 公式 |
|---|---|
| `CPI_total` | `C_total / IC` |
| **`CPI_steady`** | `C_steady / IC_useful` |
| `IPC_steady` | `IC_useful / C_steady` |
| `MIPS` | `IC_useful / (C_total × Tclk) × 10⁻⁶`（有效指令吞吐） |
| `CPU time` | `C_total × Tclk` |
| **结构加速比** | `IC_useful / C_steady`（单周期 CPI=1 的有效指令基准） |
| **时间加速比** | `(IC_useful / C_steady) × (Fmax_pipe / Fmax_单周期)` |

**自检恒等式（必须全 PASS，否则数据无效）**：

```
恒等式 A：C_total == IC + (F−1) + L + 2T
恒等式 B：C_steady == IC + L + 2T − C_fixed
收尾项：  D == C_total − h          （与实测一致）
```

## 4. 与大三单周期 CPU 的对比（要求点②③，重点核查）

### 4.1 单周期 CPU 基本结构与工作原理（报告须简述，素材已就绪）

> 素材来源：`pipeline/doc/ref_note.md` §1–§3（已完成梳理）+ `ref/CPU/` 源码。

| 项 | 内容（报告约 1 页 + 1 张数据通路图） |
|---|---|
| 顶层 | `cpu_top.v`，对外**仅 `clk`/`rst`** |
| 组成 | `pc_reg`（PC：`pc_pred=pc+4`，`pc_next=pc_src?pc_branch:pc_pred`）、`rom`（指令存储 4 KB，**组合读**）、`instr_decoder`（拆字段 + 五型立即数）、`regfile`（`x[31:1]`，`x0≡0`，异步读/边缘写）、`control`（硬布线主译码）、`alu`（33 位结果 + `flags{ZF,SF,CF,OF,PF}`）、`ram`（数据存储 4 KB，`wmask` 字节写） |
| 工作原理 | **一条指令在一个时钟周期内走完全部数据通路**：取指 → 译码 → 读寄存器 → ALU 运算 → 访存 → 写回；因此 **CPI ≡ 1**，但**关键路径 = 整条通路串联**（取指到写回），限制了最高频率 |
| 与流水线的差异 | ① 无段间寄存器；② **无数据冒险处理需求**（一拍完成读写）；③ 分支在顶层集中判决（`pc_src` + `flags[ZF]`）；④ 存储为组合读（大数组组合读难以映射为 BRAM） |

> 报告口径句："单周期 CPU 以面积与关键路径为代价换取 CPI≡1；本设计以 CPI>1 与流水线寄存器为代价换取更短的关键路径，性能对比的本质是这两者的权衡。"
