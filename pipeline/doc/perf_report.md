# 实验一性能分析报告（完成版 v2.1）

> 测量日期：2026-09-14 ｜ DUT：`pipeline_top`（`SOC_BUILD=0`）｜ 仿真器：Vivado 2019.2 xsim
> 器件与时序：`xc7a100tcsg324-1`，100 MHz 名义时钟（`Tclk=10 ns`）
> 原始数据：`pipeline/doc/perf_data/2026-09-14_perf_summary.csv`

## 1. 评价指标与测量口径

### 1.1 指标选择与依据

| 指标 | 含义 | 优点 | 局限 | 本报告用途 |
|---|---|---|---|---|
| **CPI** | 每条指令占用的平均周期数，`C/IC` | 与频率、工艺解耦，直接暴露流水线停顿 | 单一数值不能显示停顿构成 | **主指标** |
| **IPC** | 每周期完成的平均指令数，`1/CPI` | 便于表达吞吐并与单周期对照 | 与 CPI 信息重复 | 对照列 |
| **MIPS** | 每秒百万条指令 | 直观，便于表示实际吞吐 | 依赖时钟频率，跨设计比较会混入频率因素 | 频率维度 |
| **CPU time** | 完成程序所需时间，`C×Tclk` | 最贴近端到端运行速度 | 同样依赖频率 | 频率维度 |

选择依据如下：流水线的目标是在保持吞吐的同时缩短关键路径，因此首先用与频率无关的 CPI 衡量结构效率；单周期 CPU 每条指令一拍完成，`CPI=1`，可作为天然结构基准；MIPS 与 CPU time 则用于回答“提高最高频率能否覆盖流水线停顿损失”。因此本报告以 **CPI 为主指标、IPC 为对照、MIPS 和 CPU time 为频率维度指标**。

### 1.2 时间窗口与符号

为避免把流水线特有的停机尾部开销算入结构对比，测量同时保留三个窗口：

| 窗口 | 定义 | 用途 |
|---|---|---|
| `C_total` | 复位释放至停机自旋首个真实 EX 槽，再加停机尾 `D` 拍 | 端到端完成时间 |
| **`C_steady`** | `C_total - C_fixed = IC + L + 2T - 3` | **主对比口径** |
| `C_fixed` | `1 + D = 3`，即停机自旋 1 拍加冲刷尾 2 拍 | 解释短程序 CPI 偏高 |

单周期基线的 `IC` 不包含复位填充和停机冲刷尾。使用 `C_total` 直接对比会把流水线自己的固定开销重复计入，因此结构对比采用 `C_steady`。

| 符号 | 测量判据 |
|---|---|
| `IC` | EX 槽控制字非全零的真实指令槽数，包含末尾停机自旋指令；气泡/复位槽控制字全零 |
| `IC_useful` | `IC-1`，剔除末尾停机自旋后的有效指令数 |
| `F` | 首个真实 EX 槽的沿号，本轮各档实测为 1 |
| `L` | `stall` 拉高的沿数，即 load-use 冻结拍数 |
| `T` | `br_taken` 有效次数，包含 taken 分支、`jal` 和 `jalr` |
| `h` | 停机自旋首个真实 EX 槽沿号，以真实槽且 `idex_pc==br_target` 连续 2 拍判定 |
| `D` | 停机尾拍数，本轮实测为 2 |

### 1.3 公式与恒等式自检

| 指标/校验 | 公式 |
|---|---|
| `CPI_total` | `C_total / IC` |
| **`CPI_steady`** | `C_steady / IC_useful` |
| `IPC_steady` | `IC_useful / C_steady` |
| `MIPS` | `IC_useful / (C_total × Tclk) × 10^-6` |
| `CPU time` | `C_total × Tclk` |
| 结构加速比 | `S_struct = IC_useful / C_steady`，单周期 `CPI=1` |
| 频率加速比 | `S_freq = Fmax_pipe / Fmax_single` |
| 时间加速比 | `S_time = S_struct × S_freq` |

每档必须满足：

```text
C_total  = IC + (F - 1) + L + 2T
C_steady = IC + L + 2T - C_fixed
residual = C_steady - (IC + L + 2T - C_fixed) = 0
```

### 2.3 停顿构成与规模趋势

在稳态窗口中，停顿可按 `IC_useful + L + 2(T-1) = C_steady` 分解，其中 `T-1` 排除了末尾停机自旋的重定向：

- load-use 冻结占 `C_steady` 的 0%（`test0`、`cover`）到 10.5%（`hazard`）；`sort` 为 4.1%。
- 非停机分支/跳转冲刷占 0%（`test0`）到 23.8%（`sort`），是长程序的主要额外开销。
- 固定开销 `C_fixed/C_total` 从 `test0` 的 25.0% 降至 `loop128` 的 0.17%，说明短程序 CPI 偏高主要来自停机固定开销。
- `loop8/32/128` 中 `L=2N`、`T=N`，`CPI_steady` 从 1.349 收敛至 1.397，反映循环体自身的停顿结构。

三个规模档包含重复的 load-use 与回边分支，用于观察停顿随规模的收敛。当前性能 TB 只断言控制流收敛，不把 `x8` 终值作为功能正确性证据；这是一项测试范围限定，并非已确认的 RTL 缺陷。此前的 L1 线索因见证程序期望值错误已撤销，审计记录见 `pipeline/doc/known_issues.md`。

## 3. 与大三单周期 CPU 的对比

### 3.1 单周期 CPU 结构与工作原理

单周期参考工程顶层为 `ref/CPU/cpu_top.v`，对外只有 `clk` 和 `rst`。主要组成如下：

| 模块 | 作用 |
|---|---|
| `pc_reg` | 产生 `pc+4` 或分支目标 `pc_branch` |
| `rom` | 4 KB 指令存储，组合读 |
| `instr_decoder` | 拆分指令字段并生成五型立即数 |
| `regfile` | `x[31:1]`，`x0` 恒为 0，异步读、时钟沿写 |
| `control` | 硬布线主译码 |
| `alu` | 33 位结果与 `ZF/SF/CF/OF/PF` 标志 |
| `ram` | 4 KB 数据存储，组合读、按字节掩码写 |

一条指令在一个时钟周期内完成“取指 → 译码 → 读寄存器 → ALU → 访存 → 写回”，所以 `CPI=1`，但取指到写回的整条通路都位于同一关键路径中。它没有段间寄存器，也不需要流水线数据冒险处理；分支由顶层集中判决，组合读存储器则限制了大容量 BRAM 映射和最高频率。

### 3.2 基线来源与可比性

基线优先采用组内成员大三阶段单周期 CPU 的实验数据。当前仓库没有找到原始大三报告数字，因此对只读副本 `ref/CPU/` 做了同器件、同工具、同约束复测，并明确标注为“本轮实测”：

| 检查项 | 本轮结论 |
|---|---|
| 器件 | `xc7a100tcsg324-1` |
| 工具 | Vivado 2019.2 |
| 时钟约束 | 100 MHz（10 ns） |
| 同源程序 | 仅 `test0`、`test1`、`sort` |
| 单周期拍数 | `test0/test1/sort = 11/20/178` |
| 单周期 CPI | 按每条指令一拍定义为 1.00，并由仿真交叉验证 |

`ref/CPU` 的 ROM/RAM 在综合时需要初值才能保留数据通路；本轮综合副本只增加 `$readmemh` 初值和 PC 上电值，不增加或删除逻辑，属于测量条件，不改变参考设计。详见 `pipeline/doc/ref_baseline_measured.md`。

### 3.3 结构层对比

| 程序 | 单周期实测拍数 | 单周期 CPI | 流水线 C_steady | 流水线 CPI_steady | 结构加速比 `IC_useful/C_steady` |
|---|---:|---:|---:|---:|---:|
| test0 | 11 | 1.000 | 9 | 1.000 | 1.000 |
| test1 | 20 | 1.000 | 21 | 1.167 | 0.857 |
| sort | 178 | 1.000 | 244 | 1.386 | 0.721 |

结构加速比小于 1 并不矛盾：流水线的 `C_steady` 包含 load-use 冻结和分支冲刷，而单周期没有这些停顿；流水线的潜在收益来自更高的 `Fmax`。

## 4. 资源与时序综合

两种设计均在 Vivado 2019.2、`xc7a100tcsg324-1`、10 ns 时钟约束下，使用两阶段流程综合。存储器保持字节数组实现，均未映射为 BRAM；因此 LUT 绝对值主要反映存储实现方式，不能直接解释为控制逻辑规模。

| 设计 | Slice LUT | FF | BRAM | WNS(ns) | 关键路径(ns) | Fmax估计(MHz) |
|---|---:|---:|---:|---:|---:|---:|
| 单周期（ref/CPU） | 141,854 (223.74%) | 33,768 (26.63%) | 0 | -2.950 | 12.846 | 77.22 |
| 流水线 | 142,009 (223.99%) | 34,159 (26.94%) | 0 | -2.782 | 12.646 | 78.24 |

两者均超过 XC7A100T 的 LUT 容量，表中 Fmax 是 post-synthesis 估计值，不代表当前版本可以直接上板实现。流水线 WNS 改善 0.168 ns，Fmax 仅提升 `78.24/77.22 - 1 = 1.32%`；关键路径仍受组合存储和译码逻辑影响。

频率维度使用 `T=C/f` 推算，不另做多次综合：

| 频率口径 | 用途 | 计算 |
|---|---|---|
| 100 MHz（名义） | 与大三单周期在同频条件下比较 | 按 `C×10 ns` 计算 CPU time 和 MIPS |
| `Fmax_pipe` | 估算流水线实际可达到的最高频率 | 按 `C/Fmax_pipe` 计算 |
| `Fmax_single` | 估算单周期基线实际可达到的最高频率 | 按 `C/Fmax_single` 计算 |

上述口径是基于综合结果的换算，不另做多次综合。若缺少某一设计的 Fmax，应只报告结构层结论，不对缺失数据进行推算。

## 5. 系统层结论

频率加速比为 `S_freq = 78.24/77.22 = 1.0132`。将其与结构加速比相乘，得到基于有效指令窗口的时间加速比：

| 程序 | 结构加速比 | 频率加速比 | 时间加速比 `S_struct×S_freq` |
|---|---:|---:|---:|
| test0 | 1.000 | 1.013 | 1.013 |
| test1 | 0.857 | 1.013 | 0.868 |
| sort | 0.721 | 1.013 | 0.731 |

当前综合条件下，频率收益不足以覆盖流水线结构停顿：`test1` 和 `sort` 的有效指令窗口仍慢于 CPI=1 的单周期基线。若按各自 Fmax 计算完整 `C_total`，流水线相对单周期的时间比分别约为 0.929、0.844、0.730；端点停机窗口会改变绝对值，但不改变结论方向。

## 6. 结论与改进方向

1. 流水线稳态 CPI 在同源主负载上为 1.000、1.167、1.386，在规模档收敛到约 1.40；主要额外开销来自 taken 分支/跳转冲刷，其次是 load-use 冻结。
2. 停机固定开销占比随程序规模迅速摊薄：`test0` 为 25.0%，`loop128` 仅 0.17%。
3. 同频下单周期 `CPI=1`，流水线结构加速比为 0.721–1.000；流水线必须依靠显著提频才可能获益。
4. 当前 post-synthesis Fmax 只提高 1.32%，不足以抵消 `sort` 等负载的 CPI 损失。优化优先级应为减少分支冲刷、完善 load-use 前递，并将 ROM/RAM 改为可推断 BRAM 后重新综合。
