## 1. 指标与测量口径

CPI 是主指标，因为它与频率、工艺解耦，直接反映流水线停顿；IPC 作为对照列；MIPS 和 CPU time 用于频率维度。TB 统计 EX 槽中的真实指令、load-use 冻结和 taken 重定向，并对每档执行恒等式校验。

末尾 `beq x0,x0,0` 是停机自旋指令，计入 `IC`，因此定义：

- `IC_useful = IC - 1`：剔除停机自旋后的有效指令数；
- `C_total = h + 2`：停机首个真实 EX 槽后再计 2 拍冲刷尾；
- `C_fixed = 3`：停机自旋 1 拍 + 冲刷尾 2 拍；
- `C_steady = C_total - 3`；
- `CPI_total = C_total / IC`，`CPI_steady = C_steady / IC_useful`，`IPC_steady = IC_useful / C_steady`。

每档必须满足：

```
C_total  = IC + (F - 1) + L + 2T
C_steady = IC + L + 2T - C_fixed
residual = C_steady - (IC + L + 2T - C_fixed) = 0
```

### 2.1 停顿构成

用 `IC_useful + L + 2(T-1) = C_steady` 分解稳态窗口，可避免把停机重定向重复计入：

- `load-use` 冻结占 `C_steady` 的 0%（test0/cover）到 10.5%（hazard）；sort 为 4.1%。
- 非停机分支/跳转冲刷占 0%（test0）到 23.8%（sort），是长程序的主要额外开销。
- `C_fixed/C_total` 从 test0 的 25.0% 降至 loop128 的 0.17%，说明短程序的端到端 CPI 偏高主要来自固定停机开销。
- loop8/32/128 中 `L=2N`、`T=N`，`CPI_steady` 从 1.349 收敛到 1.397，反映循环体本身的停顿结构。

规模档命中已知缺陷 L1（累加寄存器自 RAW 与 load-use 组合），故只使用其 `IC/L/T/C` 计数和控制流收敛断言，不使用累加寄存器终值作为功能判据。

## 3. 单周期基线

仓库内 `ref/CPU/` 是组内大三阶段单周期 CPU 的只读副本。本轮使用同源镜像在 xsim 下实测，结果为 test0/test1/sort 的 11/20/178 拍；单周期每条指令一个周期，CPI 按定义为 1.00。单周期结构为：组合读 ROM → 译码/寄存器异步读 → ALU → 组合读 RAM → 边缘写回，整条通路位于一个周期内，因此 CPI=1 但关键路径长。

同源可比范围仅为 test0、test1、sort；覆盖档和规模档含单周期译码器不支持的指令，不参与单周期对比。

| 程序 | 单周期实测拍数 | 单周期 CPI | 流水线 C_steady | 流水线 CPI_steady | 结构加速比 `IC_useful/C_steady` |
|---|---:|---:|---:|---:|---:|
| test0 | 11 | 1.000 | 9 | 1.000 | 1.000 |
| test1 | 20 | 1.000 | 21 | 1.167 | 0.857 |
| sort | 178 | 1.000 | 244 | 1.386 | 0.721 |

结构加速比小于 1 并不矛盾：流水线的 `C_steady` 包含 load-use 冻结和分支冲刷，而单周期没有这些停顿；流水线的潜在收益来自更高 Fmax。

## 4. 资源与时序综合

两种设计均在 Vivado 2019.2、`xc7a100tcsg324-1`、10 ns 时钟约束下使用两阶段流程综合。存储器保持字节数组实现，均未映射为 BRAM；因此 LUT 绝对值主要反映存储实现方式，不能解释为纯控制逻辑规模。

| 设计 | Slice LUT | FF | BRAM | WNS(ns) | 关键路径(ns) | Fmax估计(MHz) |
|---|---:|---:|---:|---:|---:|---:|
| 单周期（ref/CPU） | 141,854 (223.74%) | 33,768 (26.63%) | 0 | -2.950 | 12.846 | 77.22 |
| 流水线 | 142,009 (223.99%) | 34,159 (26.94%) | 0 | -2.782 | 12.646 | 78.24 |

两者均超过 XC7A100T 的 LUT 容量，表中 Fmax 是 post-synthesis 估计值，不代表当前版本可以直接上板实现。流水线 WNS 改善 0.168 ns，Fmax 仅提升 `78.24/77.22 - 1 = 1.32%`；关键路径仍受组合存储/译码影响。

## 5. 系统层结论

频率加速比：`S_freq = 78.24 / 77.22 = 1.0132`。将其与结构加速比相乘，得到基于有效指令窗口的时间加速比：

| 程序 | 结构加速比 | 频率加速比 | 时间加速比 `S_struct*S_freq` |
|---|---:|---:|---:|
| test0 | 1.000 | 1.013 | 1.013 |
| test1 | 0.857 | 1.013 | 0.868 |
| sort | 0.721 | 1.013 | 0.731 |

因此，当前综合条件下频率收益不足以覆盖流水线的结构停顿：test1 和 sort 的端到端时间仍慢于 CPI=1 的单周期基线。若直接按各自 Fmax 计算总窗口，test0/test1/sort 的流水线相对单周期时间比分别约为 0.929、0.844、0.730；差异来自端点停机窗口的测量常数，结论方向一致。

## 6. 结论与改进方向

1. 流水线稳态 CPI 在同源主负载上为 1.000、1.167、1.386，在规模档收敛到约 1.40；主要额外开销来自 taken 分支/跳转冲刷，其次是 load-use 冻结。
2. 停机固定开销占比随程序规模迅速摊薄，test0 为 25.0%，loop128 仅 0.17%。
3. 同频下单周期 CPI=1，因此流水线结构加速比只有 0.721–1.000；流水线必须依靠显著提频才可能获益。
4. 当前 post-synthesis Fmax 只提高 1.32%，不足以抵消 sort 等负载的 CPI 损失；优化优先级应为减少分支冲刷、完善 load-use 前递，并将 ROM/RAM 改为可推断 BRAM 后重新综合。
