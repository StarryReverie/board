## 第一章 项目概述

### 1.1 项目构成与设计范围

项目由三个层次组成。

处理器核心是 RV32I 五级流水线处理器。

UART IP 是接口控制器，实现串行数据的发送与接收。

SoC 是处理器核心、UART IP 与复位电路的整机装配。

处理器实现 26 条 RV32I 指令，分为运算类、传送类与控制类，控制器采用硬布线结构。

UART 实现全双工收发，帧格式为 8N1，波特率为 115200。

外设采用统一编址，程序使用 lw 与 sw 指令访问。

软件采用程序查询方式完成收发。

程序镜像在综合阶段固化于指令存储器，上电后从地址 0 开始执行。

主机通过 USB 转串口与 SoC 通信。

### 1.2 三级工程结构

处理器核心的代码位于 pipeline/src 目录，包含 RTL 源码、宏定义、测试平台与脚本。

UART IP 的代码位于 UART/src 目录，包含 IP 顶层、发送模块、接收模块与测试平台。

SoC 集成代码位于 soc 目录，包含顶层装配、复位同步、数据侧译码、约束文件、固件与系统测试。

## 第二章 处理器核心设计

### 2.1 五级流水线结构

指令执行采用取指、译码、执行、访存、回写五个流水级。

相邻流水级之间由四组寄存器锁存中间结果，分别是 if_id、id_ex、ex_mem 与 mem_wb。

指令存储器与数据存储器在物理上分离，取指与访存分别使用各自的端口。

整机采用单一时钟，复位信号为异步高电平有效。

数据通路采用标准五级结构，本项目没有改动，后续页面说明本项目的控制与冒险处理方式。

图：五级流水线结构框图。

### 2.2 指令集

处理器实现 26 条指令，属于 RV32I 子集。

运算类指令 19 条，其中 R 型 10 条、I 型 9 条。

传送类指令 3 条，分别是 lui、lw、sw。

控制类指令 4 条，分别是 beq、bne、jal、jalr。

汇编伪指令 nop、j、ret、li、mv 由汇编器展开为上述指令。

表格：指令分类与编码。

### 2.3 冒险处理

数据相关采用前递处理，把 EX/MEM 与 MEM/WB 两个流水段的结果送到执行级的输入端。

load-use 相关采用冻结处理。当加载指令之后紧接使用其结果的指令时，程序计数器与 IF/ID 寄存器保持一个周期不变，ID/EX 寄存器写入气泡。

控制相关采用冲刷处理。分支指令在执行级判决，跳转成立时冲刷 IF/ID 与 ID/EX 两个流水段中的指令。

结构相关由指令存储器与数据存储器的分离消除。

表格：冒险类型、处理手段、代价。

### 2.4 前递优先级

前递是把已经产生但尚未写回的结果直接送到执行级的输入端。

当 EX/MEM 与 MEM/WB 两个流水段同时命中同一个源寄存器时，选择 EX/MEM 的结果，因为该结果在时间上更接近当前指令。

波形中展示 fwd_a_sel 与 fwd_b_sel 的取值，以及被前递的两级结果与算术逻辑单元输入的对齐关系。

图片：前递优先级波形。

### 2.5 load-use 冻结

load-use 相关是指加载指令的读出数据在访存级结束才可用，而紧随其后的指令在执行级就需要该数据。

处理方式是冻结一个周期，随后由 MEM/WB 前递提供数据。

波形中 stall 信号的高电平持续一个周期。

在该周期内，程序计数器与 IF/ID 寄存器保持不变，ID/EX 寄存器写入气泡。

图片：load-use 冻结波形。

### 2.6 分支处理

分支默认预测为不跳转，在执行级比较两个操作数。

跳转成立时，下一个周期将 IF/ID 寄存器置为 NOP 指令，将 ID/EX 寄存器的控制位清零，并把程序计数器置为分支目标地址。

每次跳转成立损失两个周期。

波形中展示 br_taken 与 br_target 信号、程序计数器的跳变，以及被冲刷的两条指令。

图片：分支冲刷波形。

### 2.7 五级流水线运行总览

波形展示连续若干周期内，五条不同指令分别处于五个流水级。

取指与访存使用不同的存储器，两者不发生冲突。

波形展示了流水级的推进与段间寄存器的锁存关系。

图片：五级流水线运行总览波形。

## 第三章 UART 接口 IP 设计

### 3.1 帧格式与波特率

收发采用 8N1 帧格式。

板载时钟频率为 100 MHz，目标波特率为 115200，每个比特对应约 868 个时钟周期，取整误差约为 0.0064%。

位节拍由 clk_en 分频脉冲产生，整机使用单一时钟。

波形中一帧由起始位、八位数据与停止位组成，帧内跳变落在整数比特边界。

图片：8N1 帧时序图与实测波形（`soc/doc/sim_shots/exp2/1_frame868_20260915.png` + `ppt/assets/uart-frame.png`）。

### 3.2 收发模块

发送模块采用 8N1 发送状态机，发送忙碌时忽略新的发送请求。

接收模块在每个比特的中心位置采样，输入信号先经过两级寄存器同步，以消除亚稳态。

### 3.3 UART IP 顶层

uart_ip_top 是 UART IP 的顶层模块，内部包含寄存器层，并实例化发送模块与接收模块。

该模块对外只提供一条从机总线与两条串行引脚，不依赖宿主处理器。

寄存器映射为三个 32 位字槽。TX 槽写入待发送字节，STAT 槽读出状态位，RX 槽读出接收字节并清除有效标志。

表格：字槽地址与位定义。

### 3.4 统一编址

统一编址是把外设寄存器与数据存储器放在同一个地址空间中。

本设计使用 lw 指令读取外设，使用 sw 指令写入外设，不增加新的指令。

UART 窗口的基地址为 0x4000，TX 位于偏移 0，STAT 位于偏移 4，RX 位于偏移 8。

地址译码分为两级，dbus_decode 在访存级选择数据存储器或 MMIO 窗口，UART IP 内部根据地址低位选择字槽。

波形中写发送与读接收在同一窗口完成，回显帧与注入字节一致。

表格：地址映射。

图片：统一编址访问波形（`soc/doc/sim_shots/exp2/4e_full_chain_overview_20260915.png` + `ppt/assets/exp2-mmio.png`）。

### 3.5 发送忙碌状态

STAT 寄存器的第 0 位表示发送忙碌，包含两种状态：已接受但尚未开始移位，以及正在移位。

写操作仅在发送空闲时被接受。

该定义使软件在 busy 为 0 时写入数据不会覆盖尚未发送的字节。

波形中第一次写入发生在空闲时而被接受，第二次写入发生在移位期间而被丢弃。

图片：忙写丢弃波形（`soc/doc/sim_shots/exp2/3b_busy_write_dropped_20260915.png` + `ppt/assets/exp2-duplex.png`）。

## 第四章 SoC 集成设计

### 4.1 SoC 装配

soc_top 实例化三个模块：pipeline_top、uart_ip_top 与 reset_sync。

数据侧译码模块 dbus_decode 位于处理器的访存级，根据访存地址选择数据存储器或 UART。

处理器通过 mmio 总线端口连接外设，soc_top 内部把 reg_off 信号适配为 UART IP 的地址。

访存在一个周期内完成，外设访问不插入等待周期。

图：SoC 装配结构图。

### 4.2 复位与引脚

reset_sync 对板载复位按键做异步置位、同步释放处理，输出处理器使用的异步高电平有效复位信号。

整机使用单一时钟，频率为 100 MHz。

引脚分配：时钟为 T5，uart_tx 为 T4，uart_rx 为 N5，rst_n 为 P15。

接收引脚在 UART IP 内部经过两级同步。

### 4.3 固件

console 固件是 CPU 与 UART 的集成应用。

固件在启动时初始化数据区，随后逐字符轮询 TX_BUSY 状态并发送 banner 字符串，之后进入回显循环：轮询 RX_VALID 状态，读取到字节后回发。

固件使用的指令均属于 26 条指令子集。

字符串按字存入数据区，发送时拆出最低字节。

### 4.4 程序固化

程序通过 .vh 文件在综合阶段写入指令存储器的初值，上电后从地址 0 开始执行。

更换程序需要重新生成 .vh 文件、重新综合、重新烧录。

数据存储器不复位，固件在启动时初始化数据区，保证复位后重新运行的结果一致。

## 第五章 验证与性能分析

### 5.1 验证方法

测试分为三类。

处理器功能测试包含模块级测试与程序级测试。

模块级测试逐个检查 RTL 模块的端口时序与功能。

程序级测试运行汇编程序，其中指令覆盖程序覆盖 26 条指令，其他程序覆盖数据相关、load-use 相关与分支跳转。

外设测试对 UART IP 检查帧格式、状态位、发送忙碌时写丢弃、读取时清除有效标志与全双工并发。

系统测试使用行为级串口模型驱动整机运行固件，检查 banner 字节序列、回显往返与复位后重新运行。

测试平台在仿真结束时自动比对期望值与实际值，并输出通过或失败。

处理器核心的回归测试共 23 项，覆盖模块级、程序级、性能与顶层用例，一次运行全部通过，无缺失或超时。

三类测试均已通过。

### 5.2 性能指标与测量口径

本设计以 CPI 为主指标，以 IPC 作为对照，MIPS 与 CPU 时间用于频率维度的分析。

测量保留三个时间窗口。C_total 是复位释放到停机的周期数。C_steady 是剔除停机与冲刷尾部开销后的周期数。C_fixed 是固定开销。结构对比使用 C_steady。

每档数据满足恒等式 C_total = IC + (F-1) + L + 2T。

其中 F 是首个真实 EX 槽的沿号，本次测量为 1。L 是 load-use 冻结周期数，T 是跳转成立次数。

### 5.4 与单周期处理器的对比

单周期参考工程在一个时钟周期内完成一条指令，CPI 恒为 1。

流水线在相同源程序上的结构加速比 IC_useful / C_steady 小于 1。

资源与时序综合在同器件、同约束条件下进行。

单周期设计的 Slice LUT 为 141854，FF 为 33768，Fmax 约为 77.2 MHz。

流水线的 Slice LUT 为 142009，FF 为 34159，Fmax 约为 78.2 MHz。

两者的存储器均未映射为 Block RAM。

频率加速比约为 1.0132。

在 test1 与 sort 程序上，时间加速比小于 1，说明在该综合条件下频率收益未能覆盖流水线停顿带来的开销。

改进方向包括减少分支冲刷、改进 load-use 前递、把存储器改为可推断的 Block RAM。
